# agentcast（Hermes 用）

agentcast はエージェントの作業をブラウザでライブ観戦するビューア。
Discord には文字で経過と結果を返し、見た目のある成果物は agentcast に送ってリンクを返す、という分担にする。
会話とツール実行のミラーはゲートウェイフック（`~/.hermes/hooks/agentcast`）が自動で行うので、このスキルで扱うのは成果物の送信と操作コマンドだけ。

以下、`$SKILL_DIR` はこの SKILL.md があるディレクトリ。設定は `~/.config/live-view.json`（`{"url": "...", "token": "..."}`）か環境変数 `LIVE_VIEW_URL` / `LIVE_VIEW_TOKEN`。

## 成果物を送る（いちばん大事なルール）

見た目で確認する成果物を作ったら、ユーザーに聞かずに毎回こうする:

1. 自己完結した HTML ファイルに保存する（CSS/JS はインライン、外部ライブラリは https の CDN のみ）。
2. 送信する。`--source` は会話のプラットフォームに合わせる（Discord なら `hermes:discord`）。

   ```bash
   node "$SKILL_DIR/scripts/push.mjs" --source hermes:discord --title "内容がわかる日本語タイトル" path/to/output.html
   ```

   出力の `URL: https://...` の行が共有リンク。
3. 返信の最後に、そのリンクを 1 行で付ける:

   ```
   📺 ライブビュー: https://.../o/xxxx
   ```

   Discord のリンクプレビューにタイトルが出るので、リンクの前に説明を重ねない。

修正を頼まれたら、同じ手順で新しい版を送り、新しいリンクを返す（前の版のリンクも残るので見比べられる）。
グラフが 1 枚だけのような小さな成果物でも送ってよい。逆に、文章だけの回答は送らない。

## コマンド

| 言われたこと | すること |
|---|---|
| 「ライブビュー」「画面で見せて」 | 設定の `url` を返す。作業中の様子と成果物の一覧が見られると一言添える |
| 「ライブビュー復元」 | `node "$SKILL_DIR/scripts/restore.mjs" --source hermes` を実行し、表示されたログ行数と成果物数を返す |
| 「ライブビュー オフ」 | `mkdir -p ~/.cache/live-view && touch ~/.cache/live-view/hermes-off`（会話のミラーだけ止まる。成果物の送信は続けてよいか確認する） |
| 「ライブビュー オン」 | `rm -f ~/.cache/live-view/hermes-off` |
| 「プロジェクター用」「成果物だけ表示」 | 設定の `url` の末尾に `/?panes=output` を付けて返す（`?panes=console` なら経過だけ） |

## うまくいかないとき

- `Push failed: 401` → トークンが違う。`~/.config/live-view.json` の確認をユーザーに頼む。
- 接続エラーやタイムアウト → サーバーが休止中の可能性がある。1 分ほど待って 1 回だけ再送する。
- Codex ランタイムで動いていて、ネットワークやキャッシュ書き込みがサンドボックスに拒否される → ユーザーに README の「Codex ランタイムで使う場合」を案内する。代わりに `AGENTCAST_CACHE_DIR` を作業ディレクトリ内に向けると、キャッシュだけは書ける。
- リンクを開いて「まだサーバーに読み込まれていません」と出た → 「ライブビュー復元」を実行する。
